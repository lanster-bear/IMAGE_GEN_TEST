# Rules · 工作规则

## 四项原则

1. 思考先于编码：确认需求与事实，声明假设；存在会改变结果的歧义就问。列出真实取舍，不隐藏不确定性。
2. 简单优先：以最少必要代码完成任务。当前零依赖本地方案够用时，不引入框架、数据库或账号系统。
3. 精确修改：每一行变更必须可追溯到当前请求。保留已有配置与数据，不顺手重构或删除旧文件。
4. 目标驱动：先定义验收项。Bug 先增加复现测试；修改后运行相关测试与项目检查，再记录证据。

## 密钥和费用

- 不将 `Image_key.txt`、`.env`、真实 Key、远端带签名 URL、完整请求 Authorization 输出或提交。
- 只能由服务端访问 Key。前端只调用同源本地 `/api/*`。
- 不上传提示词与原图到与任务无关的服务。
- 实际出图会计费，不做批量盲测、不自动重试，不把超时理解为未计费。
- 失败错误需脱敏；输出 URL 保存成本地文件，不将远端凭证 URL暴露给前端。

## 运行与修改

- 当前项目只面向单机、单服务进程。不要同时启动多个服务操作同一 `.data`。
- 不删除 `.data/` 或 `outputs/` 来“清理”。要清理先取得用户明确授权。
- 更新服务前确认任务已完成。开发 watch 重启也会中断任务。
- 任何远程发布、Git 推送、服务商账号或密钥修改都需额外用户请求。
- 用户授权公开源码时，按 [publishing](publishing.md) 核验实际提交内容；忽略规则不能代替暂存区检查。不上传个人任务、提示词、原图、exe 或旧构建中的密钥副本。
- 不并发修改同一模块；未明确要求时不启动子 Agent。

## 交接要求

任务结束更新 worknow、taskshot、handoff 和验证记录。写清“已验证 / 未验证 / 限制”，给出实际命令或产物。不要将本地模拟测试写成真实服务商成功。
